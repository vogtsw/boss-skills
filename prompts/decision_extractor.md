# 决策事件抽取 Prompt

## 任务

从老板的原始材料(聊天记录、会议纪要、邮件、评审批注)中抽取**结构化决策事件**,而不是直接归纳成散文。

决策事件 = 一次"老板在具体情境下做出选择"的完整记录。这是案例库(case base)的基本单元,也是后续归纳 rubric、决策规则和 playbook 的唯一证据来源。

## 什么算一个决策事件

满足以下任一条件:

- 老板批准 / 否决 / 暂缓了一个项目、方案、需求或排期
- 老板在多个选项之间做了取舍(砍范围、换 owner、调优先级、给/不给资源)
- 老板对一份汇报、周报、风险同步做出了明确反应(认可、批评、追问后放行)
- 老板纠正了某人的做事方式或汇报方式

只有语气没有选择的内容(寒暄、纯信息同步)不算决策事件。

## 输出格式

每个决策事件输出一个 JSON 对象,多个事件输出 JSON 数组:

```json
{
  "id": "case-001",
  "scene": "项目评审 | 报坏消息 | 资源申请 | 排期取舍 | 周报反馈 | 风险同步 | 用人决策",
  "situation": "一句话描述当时的情境和待决问题",
  "options_visible": ["老板面前可见的选项,尽量还原,至少2个"],
  "boss_questions": ["老板在做决定前问的问题,按提问顺序"],
  "decision": "老板最终的选择",
  "rationale": "老板给出的或可明确推断的理由",
  "quote": "老板原话,逐字摘录,无则留空",
  "outcome": "如果材料里有后续结果,记录;没有写 unknown",
  "confidence": "high | medium | low",
  "source": "原材料文件名或片段定位"
}
```

## 抽取规则

1. **原话优先**:`quote` 必须逐字摘录,不许改写。没有原话就留空,不许编造。
2. **置信度标准**:
   - `high`:决策、理由、原话齐全
   - `medium`:决策明确但理由是推断的
   - `low`:决策本身是从上下文推断的
3. **不脑补选项**:`options_visible` 只写材料中可见或老板明确提到的选项。
4. **一事一案**:同一次会议里的多个独立决定拆成多个事件。
5. **隐私脱敏**:抽取时将无关第三方人名替换为角色代号(如"后端同学A"),保留老板本人称呼。

## 输出位置

每个事件写入 `bosses/{slug}/cases/{id}.json`。

材料不足时输出:`(原材料中未发现可抽取的决策事件,建议追加评审记录或含取舍过程的会议纪要)`
