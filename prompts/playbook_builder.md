# Playbook 生成 Prompt(场景工作流)

## 任务

把老板处理特定事件的流程沉淀为**可一步步执行的 SOP 工作流**,写入 `bosses/{slug}/playbooks/`。

playbook 与 management.md 的区别:management.md 是建议清单,playbook 是带状态和分支的流程——用户可以照着走,skill 可以照着演。

## 默认覆盖的场景

按 cases 中出现过的场景生成,常见包括:

- `report-bad-news.md` 报坏消息
- `request-resource.md` 要资源
- `project-pitch.md` 项目立项/提案
- `weekly-report.md` 周报/例行汇报
- `risk-escalation.md` 风险上报

只为有案例支撑的场景生成 playbook;没有证据的场景跳过。

## Playbook 格式

```markdown
# Playbook: 报坏消息

## 适用情境
项目延期、线上事故、目标达不成,需要主动向老板同步。

## 前置检查(进会议室/发消息前必须备齐)
- [ ] 延期/影响的量化数字
- [ ] 已做的补救动作
- [ ] 需要老板拍板的具体事项(不超过2个)

## 步骤

### Step 1: 第一句话给事实
- 你说: "{项目}延期{X天},影响{范围}"
- 老板预期反应: 追问"为什么现在才说" (如果超过24小时) / 点头继续听 (如果及时)
- 失败分支: 如果你先解释困难 → 老板打断,印象分扣减 → 回到事实

### Step 2: 给补救与代价
- 你说: 已做了什么、还差什么、不补救的代价
- 老板预期反应: "owner是谁" / "还需要什么"

### Step 3: 要决策
- 你说: "需要你拍板{具体事项}"
- 老板预期反应: 当场拍板或给出时间点

## 老板的雷区(本场景)
- 被动暴露(他自己发现)
- 只报问题不带方案
- 把锅甩给其他团队

## 证据
- case-002: "..."(原话摘录)
- case-007: ...
```

## 生成规则

1. 每个 Step 必须有"老板预期反应",来源是 cases 中老板的真实反应;无案例则标注 `(推断,置信度低)`。
2. 失败分支必须写:用户做错时老板会怎样、如何挽回。
3. 雷区只写本场景内的,通用雷区放 persona.md。
4. 末尾必须列证据 case id。

## 运行时用法(写给 boss skill 的)

- 用户问"怎么跟老板说X" → 匹配场景 → 按 playbook 步骤给话术
- 用户要对练 → skill 扮演老板,按"老板预期反应"和失败分支推进多轮对话
